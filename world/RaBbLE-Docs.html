Technical reference for the RaBbLE web presence — what the Collective is, how this site is put together, how the entity renders, and how chat reaches the coordination engine.

What is RaBbLE

RaBbLE is a Behavioral Learning Engine — a personal system being built to observe its user, learn patterns, infer intent, and delegate action. The B in the acronym is a floating slot: Boundless is canonical, but Becoming, Brilliant, and Behavioral are all valid states.

RaBbLE is the entity; the Collective is its scaffolding. Expression is ambient and ongoing, not transactional — the entity you see on these pages is a peer collaborator taking shape, not a chat product.

The visual language is not decoration — it is character made visible. Every state change (idle → thinking → speaking) is expressed through the entity's appearance.

World Architecture

RaBbLE-World is intentionally static: plain HTML, CSS, and JavaScript with no bundler, no framework, no build step. Visual identity and entity rendering arrive as shared bundles, so page code stays structural.

Loading order (all pages)

<script src="js/RaBbLE-aether.js"></script>   injects Aether CSS + failure banner
<script src="js/RaBbLE-NeBuLA.js"></script>   NeBuLA bundle — defines <rabble-entity>

<link rel="stylesheet" href="css/RaBbLE-theme.css">   alias bridge to Aether vars
<link rel="stylesheet" href="css/RaBbLE-chrome.css">  shared chrome (global nav)
<link rel="stylesheet" href="css/RaBbLE-[page].css">  page layout only

Rules the pages follow

Colors only via RaBbLE-theme.css vars (never raw hex). Fonts owned by Aether. The entity element <rabble-entity> is defined inside the NeBuLA bundle and never redefined in World. Page registry lives in js/RaBbLE-pages.js; the global ◈ navigator (bottom-right of every page) is mounted by js/RaBbLE-page-runtime.js.

The Entity — Rendering & States

The entity is rendered by NeBuLA's <rabble-entity> custom element: a particle nebula with two eyes — magenta and cyan — each floating over a dark portal disc. Eyes track the cursor, blink on a finite-state machine, and perform saccades when idle.

States

StateExpression
idleSlow drift, periodic blinks and saccades.
thinkingHigher waveform frequency, accelerated motion.
speakingStrong waveform amplitude while responding.
bootManifestation — particles converge, portals trace, eyes open.
const el = document.querySelector('rabble-entity');
el.setEntityState('thinking');   // idle | thinking | speaking
el.setEntropy(0.6);              // 0–1, drives motion intensity
el.triggerBoot();                // replay the manifestation sequence

State changes are broadcast as a rabble:entity-state event on window, so page chrome (statusbars, pills) can mirror the entity.

Chat API (sCoRE)

Chat is served by RaBbLE-sCoRE, a FastAPI coordination engine. The World chat surface posts conversation history and streams the reply. 

POST {base}/api/v1/chat
Content-Type: application/json
X-API-Key: <optional>

{ "messages": [{ "role": "user", "content": "..." }], "model_tier": "fast" }

→ text/event-stream — reply streams as SSE "data:" chunks

The base URL defaults to http://localhost:8000 and is overridden with window.RABBLE_API_URL. Liveness at GET {base}/health. Behind the endpoint, sCoRE routes across LLM providers and speaks as the entity.

Local-first: the chat loop runs entirely on a laptop — World pages + a local sCoRE server. Cloud deployment is deliberate, not default.

Versioning — the Five Es

The Collective versions itself in five nested layers: Epoch (architectural era) · Evolution (major capability) · Echo (visual/expressive generation) · Episode (shippable release) · Entity (the emergent whole). This site is epoch 0 · echo 0 · episode 1 — the first aired release: the entity's face, voice, and door.
